# Agent Note: 右键在指针位置打开侧边栏行菜单

Status: implemented

[English](2026-08-16-sidebar-row-context-menu.md) | 中文

## 问题

工作区浏览器中的行操作（Session 行的重命名/分叉/归档，Workspace 行的重命名/删除）此前只能通过悬停后出现的省略号触发按钮进入。右键是行级操作的标准桌面手势，桌面外壳面向鼠标用户；现有菜单已经包含全部安全操作，缺的只是一个入口。

## 决策

非空白的 Session 行和真实 Workspace 行处理 `onContextMenu`：阻止原生菜单，打开该行已有的 `Menu`，并通过 `Menu` 原语的 `getAnchorRect` 将菜单锚定在指针位置（portal 定位，因此列表出现在光标处，原语的视口钳制保证菜单不越界）。空白的「新会话」行和 Ungrouped 桶没有菜单，也不注册处理器。

指针锚点在关闭和选中时都会清除，因此省略号触发保持原有的锚定在触发按钮上的行为，后续右键也能正确重新定位。打开菜单不会打开或切换会话：右键不会触发行的 `onClick`。

## 备选方案

**桌面端 DOM 委托** —— 已否决。客户端外壳监听并定位行、再对省略号按钮合成点击的做法，会让菜单出现在省略号位置而非指针处，并把外壳与行的 DOM 细节耦合在一起。行操作及其背后的对话框本就归浏览器所有。

**同一次改动加入新菜单项** —— 推迟。P0 与省略号动作完全一致，保证两个触发入口行为相同；新动作（删除会话、置顶、导出）留作独立的产品决策。

## 后果

右键提供的动作与省略号菜单完全一致，并定位在指针处。菜单打开期间悬浮卡片保持抑制，行为不变。两个触发入口共享同一份菜单状态，因此同一行不会同时打开两个菜单。

## 验证

`rows.client.spec.tsx` 覆盖：Session 行右键（菜单定位在指针坐标、不打开会话、分叉分发、Escape 关闭后可重新定位）、Workspace 行右键分发删除，以及无菜单的情形（空白的「新会话」行、Ungrouped 桶）。
