# Agent Note: QZH 证据布局推断

Status: implemented

[English](2026-08-22-qzh-evidence-layout.md) | 中文

## 问题

QZH Web 工作台的日志布局处理存在硬编码假设。桌面原型按字面 `/data/logs` 前缀过滤压缩包成员，Web 扫描器则通过内联条件把 QZH 服务名映射成组件。现场日志压缩包结构经常变化——新服务、改名目录、嵌套打包——导致浏览器要么丢弃文件、要么标错组件、要么把所有未知文件统一归为通用标签。组件标签原样穿透到证据包、异常聚类和 Agent 上下文，因此报告的证据链好坏只取决于浏览器的猜测，Agent 也无法核对真实的压缩包结构。

## 决定

布局识别改为两层：浏览器产出尽力而为、数据驱动的标签；Host Agent 拥有最终解释权。

浏览器端（`packages/client/ui-qzh-log-analysis/src/log-layout.ts`）改为通过数据表 `QZH_COMPONENT_RULES` 映射组件（最长匹配文件名片段优先，`qzh_agent_flush` 不会被更短的 `qzh_agent` 吞掉）；新增服务只需加一行数据，不改扫描逻辑。未命中规则的文件的保留基于路径推断的回退标签，任何固定目录前缀都不再导致丢文件。stream 分类优先看文件名（`*-error.log` 等），文件名无信号时回退到内容检查（`looksLikeErrorStream`）：前几行非空行中错误标记占多数才判为错误流，普通日志里的零星 ERROR 不会被误判。每个导入条目携带受限的首行样例（最多 4 行非空、1 KiB），外发预览展示它，证据摘要也会提交它。

Host 端（`packages/host/qzh-log-analysis`）对每个文件的样例做二次脱敏（遮盖 + 512 字符上限），并注册新的只读模型工具 `qzh_list_evidence`：返回证据包内完整文件清单（真实相对路径、逐文件样例）和异常聚类。QZH 排查方法论提示词（Host 段落、分析提示词和 `qzh` preset persona 三处）现在指示 Agent：先列证据、以现场实际目录结构为准而不是假设固定布局、浏览器 `component` 只是初始猜测、报告中的日志引用必须使用证据包内的真实相对路径。

## 备选方案

- **维持固定 `/data/logs` 布局契约**——否决：现场压缩包不保证遵循该布局，静默丢弃不匹配文件会丢失证据。
- **浏览器端完全按内容分类**——否决：浏览器没有 Agent 判断力，且不带主导性检查的内容分类会把普通日志误判为错误流，导致解析器被淹没。
- **只靠 Agent 探索、浏览器不产标签**——否决：浏览器仍需标签用于本地外发预览和聚类分组；Agent 的 `qzh_list_evidence` 从真实路径与样例重新推导结构。

## 后果

出现新服务或改名结构的现场压缩包仍能获得可用标签，且不再因目录假设丢文件。Agent 的证据视图不再受浏览器推断限制，报告引用的是实际布局。证据包每个文件多出受限的首行样例，提交前会展示在外发确认预览中；Host 对样例进行二次脱敏并设上限，作为第二道执行点。桌面原型的硬编码 `/data/logs` 扫描器不属于 Web 产品路径，保持原样。
